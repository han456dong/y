## 1. 设计目标

本原型只回答一个问题：**授权如何被用户看见。**

辰光 Agent 平台已有认证，缺的是授权（Authorization）。PRD 的核心要求是「菜单、路由、按钮随权限收敛」。因此本原型的首要任务不是再画一套漂亮的 Agent 管理界面，而是把「同一套界面，在不同身份下长什么样」这件事讲清楚。

设计上追求三点：

1. **可见的授权边界** —— 同一页面在管理员 / 运营 / 只读三种身份下，菜单与按钮实打实地变化，而不是注释说明。
2. **可解释的权限结构** —— 权限目录是「模块 × 操作」的矩阵，一眼看清谁有什么、缺什么。
3. **有态度的视觉** —— 摆脱通用 SaaS 卡片风格，用「授权账簿」的隐喻承载 RBAC 的严肃与精确。

## 2. 设计语言：授权账簿（Permission Ledger）

### 2.1 隐喻

授权这件事的本质是一本**可审计的账**：每一笔「谁能做什么」都要能追溯到角色，每一处「不能做」都该留下一条清晰的划线，而不是静默消失。原型采用「墨色账簿 + 纸面」的视觉隐喻：

- 深墨色侧边栏是账簿的硬皮封面；
- 浅纸色内容区是内页；
- 权限矩阵是账簿里最核心的表格，模块为行、操作为列；
- 被拒绝的操作不是消失，而是被**一条红线划掉**（403 页、权限透视里都能看到这条线）。

### 2.2 颜色

| 名称 | 值 | 用途 |
|---|---|---|
| 墨 ink | `#1E2A33` | 侧边栏、403 大标题、toast 底色 |
| 纸 paper | `#EEF1EE` | 页面背景 |
| 松绿 pine | `#1F6B5A` | 「已授予」、主按钮、选中态 |
| 暖金 gold | `#B97A1E` | 提示、演示身份切换、内置标记 |
| 赤陶 ember | `#A63D36` | 「未授予」、删除、403 划线 |
| 墨灰 muted | `#5F6E68` | 次级文字 |

配色刻意避开生成式页面最常见的「暖米白 + 陶土强调」（近乎 Anthropic 交互色）和「近黑 + 荧光绿」。松绿 = 授予、赤陶 = 拒绝，语义直接，且与「记账」的严肃气质一致。

### 2.3 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 标题 / 强调 | Playfair Display（衬线） | 承载「账簿」的正式感 |
| 正文 / 界面 | Inter（无衬线） | 可读性 |
| 权限码 / 数字 | 等宽（Cascadia Code 等） | 权限码、计数、指标，像账目编号 |

字体回退链针对 Windows 中文环境补齐了 PingFang SC / Microsoft YaHei / Noto Serif SC，离线打开也不崩。

### 2.4 布局

统一「侧边栏 + 顶栏 + 内容区」三段式，与 V1 原型的骨架保持一致，保证评审时能对照。

```
┌──────────┬──────────────────────────────────────┐
│ 侧边栏    │ 顶栏（面包屑 · 权限透视 · 演示身份 · 用户）│
│ (墨色)   ├──────────────────────────────────────┤
│          │ 页头（标题 · 副标题 · 主操作）         │
│ 导航      │ 提示条（当前身份的可见范围）           │
│ ─ 平台    │ 统计条 / 工具栏 / 账簿表格             │
│ ─ 系统    │ 页脚                                  │
│ 身份      │                                      │
│ 权限条    │                                      │
└──────────┴──────────────────────────────────────┘
```

对齐原则：正文一律左对齐；表格里的数字右对齐（`tabular-nums`）；权限矩阵的勾选居中。行长控制在 80 字符以内。

### 2.5 设计原则（本原型专属）

1. **权限变化是主体内容，不是边角料。** 每个页面的第一条信息是「当前身份能看到什么」。
2. **被拒绝要留下痕迹。** 403 页有划线账簿，权限透视用斜纹 + 虚线把被隐藏的按钮「钉」回原位，用户能看见自己缺了什么，而不是只看见一片空白。
3. **一处大胆，其余克制。** 视觉上最跳的是权限矩阵与 403 的划线；其余地方保持灰、绿、金三色的克制层次，不做渐变、不做圆角卡片堆叠、不做全大写 eyebrow。

## 3. 页面结构与清单

原型共 **9 个静态页面**，全部位于 `docs/ui/rbac/`，共享 `assets/prototype.css` 与 `assets/prototype.js`。

| 页面 | 文件 | 权限码 | 说明 |
|---|---|---|---|
| 封面索引 | `index.html` | 公开 | 三种身份权限对比 + 页面目录 |
| 登录 | `login.html` | 公开 | 验证码登录 + 演示身份切换 |
| 工作台 | `dashboard.html` | `dashboard:read` | 我的授权范围、未授予操作、授权变更记录 |
| Agent 管理 | `agents.html` | `agent:read` | 按钮级收敛的示范页 |
| 用户管理 | `system-users.html` | `system.user:read` | 角色分配、启停、自我保护 |
| 角色管理 | `system-roles.html` | `system.role:read` | 权限账簿（模块 × 操作矩阵） |
| 权限管理 | `system-permissions.html` | `system.permission:read` | 模块筛选、内置保护、权限码校验 |
| 403 | `forbidden.html` | 登录 | 无权限落地页 |
| 权限加载失败 | `permission-error.html` | 登录 | 默认拒绝状态 |

### 3.1 封面索引 `index.html`

原型入口。包含：

- 大幅标题「授权，应该看得见」；
- 三种身份的模块权限对比表（每一格用一串小方块表示该模块已授予的操作数）；
- 页面目录（含每页的一句话说明）。

### 3.2 登录 `login.html`

左栏是深色封面 + 三行权限示意（对应 admin 全开、知识库部分、系统管理全关）；右栏是登录表单。三个「演示身份」快捷按钮直接选择 admin / operator / viewer 进入。

### 3.3 工作台 `dashboard.html`

- 统计条：有效权限数 / 可进入模块数 / 未授予操作数 / 平台账号数；
- 「我的授权范围」：按模块画出已授予比例条（系统管理合并为一行 `system.*`）；
- 「未授予的操作」：列出当前身份缺的前几条权限，红标「未授予」；
- 「最近活动」：授权变更的时间线。

### 3.4 Agent 管理 `agents.html`

按钮级收敛的示范。同一张表，行尾操作按钮按权限显示：

- **管理员**：编辑 / 发布 / 测试 / 停止 / 删除 全部可见；
- **运营**：编辑 / 发布 / 测试 / 停止，**删除隐藏**；
- **只读**：写操作全部隐藏，只留一个「只读」标签。

打开「权限透视」后，被隐藏的按钮以斜纹 + 红色虚线钉回原位，鼠标悬停提示「无此权限」。

### 3.5 用户管理 `system-users.html`

- 管理员视角：完整表格 + 分配角色抽屉 + 添加用户弹窗；
- 本人行（陈晓）的「分配角色 / 停用 / 删除」全部禁用，体现「不能对自己操作」；
- 运营 / 只读身份访问本页：整个内容区替换为 403 守卫态（`data-required="system.user:read"`），不渲染表格。

### 3.6 角色管理 `system-roles.html`

权限矩阵是本原型视觉中心：

- 左侧角色列表（内置角色带「内置」标记，显示权限数与用户数）；
- 右侧「模块 × 操作」矩阵，模块行左侧有整组勾选框，支持三态（全选 / 半选 / 未选）；
- 矩阵顶部有已选计数与「未保存」提示；
- `admin` 角色矩阵只读（权限集合不可缩减）；内置角色的「删除角色」按钮禁用；
- 运营 / 只读身份访问本页同样进入 403 守卫态。

### 3.7 权限管理 `system-permissions.html`

- 模块筛选 chips（含 `system.` 前缀整体筛选、`custom` 自定义）；
- 内置权限带「内置」标记，删除按钮禁用；
- 创建权限弹窗内对权限码做正则校验（`模块:操作`），实时显示拆分结果，不合法时提交按钮禁用。

### 3.8 403 `forbidden.html`

- 超大「403」数字，上面一条赤陶斜线划过；
- 一句「这个页面不在你的授权范围内」；
- 划线账簿列出几个模块的授予 / 未授予状态（不泄露具体所需权限码）；
- 默认以 operator 身份打开，直接演示运营访问系统管理的后果。

### 3.9 权限加载失败 `permission-error.html`

对应 PRD FR-04 第 6 条「权限加载失败不得默认放行」。无侧边栏、无菜单，只有错误说明 + 「重新加载 / 返回登录」两个动作。

## 4. 三种身份与权限收敛机制

### 4.1 身份与权限（对齐 PRD 4.5）

| 身份 | 权限数 | 特征 |
|---|---|---|
| 管理员 admin | 63 | `is_superuser=true`，全部放行，系统管理可见 |
| 运营 operator | 27 | 业务读写 + 发布 + 测试，**无删除、无系统管理** |
| 只读 viewer | 9 | 全部业务模块只读，无任何写操作 |

原型内置了一个额外的自定义角色 `analyst`（数据分析师，12 项权限），用于演示角色管理里的「自定义角色」，不干扰三种内置角色的矩阵。

### 4.2 收敛的三个层次

| 层次 | 实现 | 效果 |
|---|---|---|
| 菜单 | 每个导航项带 `data-perm`，`applyVisibility()` 按当前身份隐藏 | 只读看不到「系统」分组 |
| 路由 | 页面 `<main data-required="...">`，无权限时切到 `guard-state` | 运营直接访问用户管理看到 403 |
| 按钮 | 按钮带 `data-perm`，无权限时 `display:none` | 运营的 Agent 删除按钮消失 |

### 4.3 权限透视（Lens）

原型的一个独有交互：顶栏「权限透视」开关。打开后，被隐藏的操作**不消失**，而是以斜纹 + 红色虚线 + `not-allowed` 光标钉回原位。这让评审者能「看见自己少了什么」，而不是对着空白的操作列猜测。

实现上通过 `body.lens-on` 覆盖 `perm-hidden` 的 `display:none`，并叠加斜纹背景。URL 参数 `?lens=1` 可直接进入透视态（用于截图）。

### 4.4 身份切换

顶栏「演示身份」分段控件切换 admin / operator / viewer，切换时在 URL 加 `?role=` 并整页刷新。角色状态用 `localStorage` 记忆（`file://` 环境下可优雅降级）。

## 5. 组件与交互规格

### 5.1 通用组件

| 组件 | 说明 |
|---|---|
| 账簿表格 `.ledger` | 主列表；行 hover、数字右对齐、等宽权限码 |
| 徽标 `.badge` | 授予（松绿）/ 未授予（赤陶）/ 内置（暖金）/ 中性 |
| 提示条 `.notice` | 绿/金/红三色，带图标，承载「当前身份可见范围」等上下文 |
| 抽屉 `.drawer` | 分配角色；从右侧滑入 |
| 弹窗 `.modal` | 创建角色 / 创建权限 / 添加用户 |
| Toast | 右下角墨色，操作反馈 |
| 权限矩阵 `.matrix` | 角色页核心；模块行 sticky、整组勾选三态 |
| 统计条 `.stat-strip` | 页面顶部四项指标，衬线大数字 |

### 5.2 关键交互

| 场景 | 交互 |
|---|---|
| 切换身份 | 顶栏分段控件 → URL 带 `?role=` 整页刷新 → 菜单/按钮重新收敛 |
| 权限透视 | 顶栏开关 → 被隐藏操作以斜纹钉回 |
| 角色权限勾选 | 点击单个格子切换；点击模块行首框整组切换；顶部计数实时更新 + 「未保存」提示 |
| 分配角色 | 打开抽屉 → 多选 → 保存 → toast「权限变更最迟 10 分钟生效」 |
| 创建权限 | 输入权限码 → 实时正则校验 → 拆分模块/操作 → 合法才允许提交 |
| 删除内置资源 | 按钮禁用 + 点击 toast「内置资源不可删除」 |
| 无权限访问 | 整页切换为 403 守卫态 |

### 5.3 按钮权限矩阵（示例：Agent 管理）

| 操作 | admin | operator | viewer |
|---|:---:|:---:|:---:|
| 新建 | ✅ | ✅ | — |
| 编辑 | ✅ | ✅ | — |
| 发布 | ✅ | ✅ | — |
| 测试 | ✅ | ✅ | — |
| 停止 | ✅ | ✅ | — |
| 删除 | ✅ | — | — |

完整矩阵见 PRD 8.4，原型在 `agents.html` 与 `prototype.js` 的 `OPERATOR_PERMS` / `VIEWER_PERMS` 中落地。

### 5.4 安全边界在原型中的表达

| PRD 规则 | 原型表达 |
|---|---|
| 不能对自己操作 | 用户管理里「本人」行的操作按钮全部禁用 |
| 内置角色不可删除 | 角色页「删除角色」对内置角色禁用，title 提示 |
| admin 权限不可缩减 | admin 角色的矩阵 `data-readonly`，保存按钮禁用 |
| 内置权限不可删除 | 权限页内置行删除按钮禁用 |
| 权限加载失败不放行 | `permission-error.html` 独立状态页 |

## 8. 使用说明

1. 直接用浏览器打开 `docs/ui/rbac/index.html`（无需服务器、无需构建）。
2. 顶栏「演示身份」切换 admin / operator / viewer，观察菜单、按钮、路由守卫的变化。
3. 打开「权限透视」，看被隐藏的操作被斜纹钉回原位。
4. 从运营身份点击侧边栏「用户管理」，或直接访问 `system-users.html?role=operator`，查看 403 守卫态。

> 注意：侧边栏「模型管理 / Prompt / 知识库 / 工具 / 对话 / 统计」与「API 密钥 / 审计 / 告警 / 系统配置」本期为占位（点击提示「不在页面范围内」），本期原型的深度集中在 RBAC 授权相关的用户 / 角色 / 权限三页与 Agent 示范页。
